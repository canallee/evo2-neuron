Evo 2 on Trainium

Arc Institute's 7B DNA language model running on torch.device("neuron") in plain PyTorch — no vortex runtime, no TransformerEngine, no flash-attn, no CUDA. The same package runs unchanged on CPU. Gated against saved H200 activations, with generic LoRA fine-tuning and a data-parallel driver for every core on the instance. Measured on AWS's public torch-neuronx 2.14 (Neuron SDK 2.33.0).

Read this before using it for science

This is a re-implementation, not Arc Institute's code. The model definition was written against ArcInstitute/evo2 and Zymrael/vortex and patched to run without CUDA, vortex, TransformerEngine, flash-attn or Triton. The weights are Arc's, unmodified; everything around them is not. Not endorsed by, or affiliated with, Arc Institute or AWS.

Only evo2-7b is validated. evo2-1b builds and runs, but Arc's 1B config sets use_fp8_input_projections: True and this port has no FP8 path — disabling it costs ~47 accuracy points, so the 1B numbers cannot be gated against anything. evo2-40b is not implemented.

It is not bit-exact against CUDA, and is not meant to be. The read-out differs from the H200 reference by 1.6e-02 (CPU) and 3.4e-02 (Trainium) in bf16 — consistent with reduction order rather than a defect. For calibration, upgrading torch from 2.12 to 2.14, which cannot change the mathematics, moves the same CPU tensor by 1.2e-02. That is small for a representation and not nothing for a downstream decision: variant effect sizes, likelihood ratios and ranked predictions can move. If a result matters, check it against the CUDA path for your own task first.

Not validated: generation and decoding, context beyond 8192, batch > 1 per core, and full fine-tuning at 7B scale.

Install and weights

The neuron device comes from AWS's public native-PyTorch backend, torch-neuronx 2.14, with neuronx-cc and nki from the Neuron pip index. On Ubuntu 24.04 the published torch-neuronx wheels need glibc 2.43 and do not load, so docs/INSTALL.md builds it from the public source, after upgrading the DLAMI's Neuron runtime to 2.35. Nothing below the device line needs any of it — the tests, the examples and the CUDA parity gate all run on a plain CPU install.

# the Neuron env from docs/INSTALL.md, then this package's deps
conda activate torch-neuron-evo2
pip install -r requirements.txt
export PYTHONPATH=$PWD/src

# works with no device and no weights: 102 unit tests, ~25 s
make test
make smoke      # every example on CPU, random weights

Weights are Arc's and are not redistributed. They download on first use. A read-out head only needs blocks 0..10, so pruning the checkpoint once cuts it from 13 GB to 4.5 GB — worth doing before a multi-rank job, where every rank reads it.

huggingface-cli download arcinstitute/evo2_7b_base evo2_7b_base.pt
python scripts/prune_checkpoint.py evo2_7b_base.pt evo2_7b_blocks0_10.pt --max-blocks 11
export EVO2_CHECKPOINT=$PWD/evo2_7b_blocks0_10.pt

Embeddings in six lines

import evo2_finetune.neuron_env as env; env.configure()   # BEFORE torch
import torch
from evo2_finetune.backbone import Evo2Backbone
from evo2_neuron import ByteTokenizer

backbone = Evo2Backbone("evo2-7b").to(env.resolve_device("neuron"))
ids, mask = ByteTokenizer().encode_batch(["ACGTACGTACGT"], max_length=8192)
hidden = backbone(ids.to("neuron"))          # (1, 8192, 4096)

Order matters

configure() must run before anything imports torch. import torch auto-loads torch_neuronx, which reads the four compiler cache directories at that moment; setting them afterwards has no effect and the run silently uses /tmp. It raises rather than letting you find out later.

Parity gates

The reference is an NVIDIA H200 running evo2 0.1.0 / vortex 0.0.2, bit-reproducible across two physical GPUs. Its activations ship in the box, so the gates are runnable rather than quotable.

The gate is the residual stream, not the read-out. hidden0 is a 0.42% correction to the residual stream by norm: it reports that something diverged and never where. And the metric on the stream is the increment delta_k = block_out.k − block_out.{k−1}, not the cumulative tensor — block 3 contributes 1.3% of block_out.3, so a completely broken attention block reads ~1.3e-02 cumulatively, inside the bf16 noise floor.

A block is flagged only if it fails both magnitude (relerr > 3e-3) and direction (1−cos > 1e-2). Both floors are calibrated against controls, not chosen.

Why magnitude alone says little at bf16

The CPU read-out from torch 2.12.1 and from torch 2.14.0 — same port, same checkpoint, same input, each bit-reproducible on its own — differs by 1.24e-02. On torch 2.12.1, flipping requires_grad on the backbone moved it by the same 1.244e-02. The entire CUDA→CPU disagreement is 1.59e-02. At this precision the magnitude is mostly reduction order; direction is the half that discriminates.

LoRA fine-tuning

The backbone is frozen; only the adapters and the read-out head train — 74 tensors, 5.2 M of 2.23 B parameters at r=8. Six objectives over four heads, chosen by the granularity of the label you have.

ObjectiveHeadLabelOutput
next-token-cetied LM headnone — the sequence itself(B, L, 512)
sequence-regressionMLPReadoutHead · ConvReadoutHeadone float vector per sequence(B, out)
sequence-classificationMLPReadoutHead · ConvReadoutHeadone class per sequence(B, out)
window-regressionWindowTrackHeadone value per 256 bp bin(B, L/256, out)
per-position-classificationPerPositionHeadone class per nucleotide(B, L, out)
per-position-regressionPerPositionHeadone value per nucleotide(B, L, out)
from evo2_finetune import build_model

model = build_model(
    objective="window-regression",      # one prediction per 256 bp bin
    alias="evo2-7b", out_dim=1, device="neuron", dtype=torch.bfloat16,
    head_kwargs={"window": 256}, gradient_checkpointing=True,
)
out = model(input_ids=ids, attention_mask=mask, labels=y, weights=w)
out["loss"].backward()

Four runnable examples ship with the repo. Each runs on CPU in seconds with --random-backbone, and on Trainium with real weights.

python examples/01_embeddings.py --device cpu --random-backbone --max-blocks 3
python examples/02_lora_lm_finetune.py --fasta genome.fa --device neuron
python examples/03_window_regression.py --device neuron

Labelled data is optional: SyntheticDNADataset plants motifs in seeded random sequence and derives sequence, window and per-base labels from them, so every example runs offline. The signal is learnable on purpose — a flat loss curve there means the harness is wrong, not that the task is hard.

Training across every NeuronCore

Warm the compiler cache with one rank first — concurrent cold compiles have been enough to kill the compile service. The cold compile of eleven 7B blocks at 8192 is a one-off 766 s; every warm step after it is 3.41 s.

# warm the NEFF cache, one rank
NEURON_RT_VISIBLE_CORES=0 python -u scripts/train_lora_ddp.py --steps 12

# then all 64 logical cores of a trn2.48xlarge

61.3× on 64 logical NeuronCores at 95.8% efficiency, 147,067 tokens/s at 8192 context. The step time moves 4.4% from one rank to sixty-four — 3.4140 s to 3.5650 s for a 64× wider batch — which is what data-parallel scaling looks like when the collective is small: the gradient payload is 10.3 MB in bf16 and fits in one bucket. Rank spread stays under 0.5% throughout, so these are throughput numbers and not straggler numbers. Only the first graph is a long compile; on torch-neuronx 2.14 the first DDP graph costs about 50 s.

Defaults are the production configuration: bf16, per-block compile, activation checkpointing, nki-scan, batch 1 per rank.

What makes it run, and what makes it fast

Three of the four production flags are not optional at seq 8192: without nki-scan the long convolution does not compile, without checkpointing the step does not fit in 24 GiB, and without per-block compile the graph exceeds the compiler's instruction limit. The figures in the last column were measured on the private-beta build this port was developed on.

LeverWhat it doesWorth
--hcl-kernel nki-scanThe Hyena modal long convolution h[s]=Σⱼrⱼaⱼˢ is the transfer function of a first-order recurrence, so it becomes a scan. C·L² → C·S·L: 512× fewer MACs at 8192.the only form that compiles at 8192

Those rewrites fix ops that fall back silently — the run completes with correct numbers and a host round-trip per step. That is why the census is a tool (scripts/check_fallback_ops.py) and not an eyeball: it clears tracking between stages, asserts the executed-op list is non-empty, and runs both dtypes, because the fallback set is dtype-dependent.

Artifact bundles

A bundle is one directory of tensors that pins everything a device port can get wrong. Dump one per device, then diff them.

FileContentsCatches
inputs.ptthe exact batches, replayeda comparison run on the wrong input
blocks0_10.ptthe residual stream, per blockwhere the port diverges
hidden0.ptthe read-out the head consumesthat it diverged
w0.pttrainable weights before step 0the two arms started differently
g1.ptgradients after the first backwarda wrong backward
wN.ptweights after N stepsa wrong optimizer step

hidden0 and blocks0_10 are captured on the first forward, where lora_B is still zero and the adapters are exactly the identity. They are pure backbone activations — which is what lets a CUDA bundle produced by one task gate a port trained on another. CPU bundles are bit-reproducible on the torch release that wrote them; the shipped ones were written by torch 2.14.0.

PYTHONPATH=src python scripts/dump_artifacts.py --device neuron --dtype bf16 \
    --inputs-from artifacts/cuda_seq200/inputs.pt --forward-only \
    --strict-determinism --out-dir artifacts/my_run
PYTHONPATH=src python scripts/dump_artifacts.py --compare \
    artifacts/cuda_seq200 artifacts/my_run

Pin the weights, do not seed them

torch.manual_seed feeds a per-device generator, so a head initialised on each device from the same seed gives CPU and Neuron unrelated weights — measured rel_err 1.419, a comparison between two different models. --init-from refuses a partial pin rather than covering some tensors and leaving the rest random.

Things that fail without saying so

Each of these produces a run that completes and is wrong, or a job that is N× slower with no error. All are handled in the shipped code; they are here because you will meet them the moment you step outside it.

If you…What happens
install the published torch-neuronx wheel on Ubuntu 24.04it installs cleanly, then import torch_neuronx fails: GLIBC_2.43 not found. Build from source (docs/INSTALL.md).
set the TORCH_NEURONX_* cache dirs after importing torchno effect; the run uses /tmp, and a permission error there surfaces as a generic "Compilation error"
leave NEURON_RT_VISIBLE_CORES=0 under torchrunevery rank would share one core — correct numbers, N× slower, no error. The driver refuses instead, naming the rank and the range.
leave the full range visible to every rankeach runtime claims all of it — Failed to initialize Neuron Runtime: status code 1 on all but one rank, naming neither cause nor culprit
address the device by local rank after narrowingDevice index 0 is out of range. Valid range is 3 to 3 — the visible set is narrowed, not renumbered
use blocks[i] = torch.compile(...)_orig_mod. is inserted into 60 of 74 parameter names, breaking adapter checkpoints
leave recompile_limit at its default of 8eleven blocks exceed it and dynamo falls back to eager, silently
read out via a forward hook on a compiled blockdynamo traces through the submodule and the hook never fires; compile_blocks() switches the read-out mode for you
use reentrant activation checkpointinga frozen backbone means block inputs do not require grad; every LoRA gradient but the topmost is dropped
skip convert_wqkv_column_split at loadq/k/v scrambled across heads, no error, read-out off by rel_err ~1.37
judge a gradient by magnitude alonelora_B is zero-init, so an absent gradient reads as a small one
pipe a long device run through tailit buffers until exit; a healthy compile looks hung

The last one has a corollary worth internalising: before believing any timing number, run make health. An orphaned process holding a NeuronCore fakes a mid-run throughput collapse, and a bimodal step-time trace is a contention signature until proven otherwise.
